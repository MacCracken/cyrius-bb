# Code + Security Audit — 2026-11-08 (0.9.2)

> **Scope**: all first-party code: `src/` (18 modules), `tests/`, `programs/`
> and `.github/workflows/`. `lib/` and `vendor/` are upstream and were read only
> to learn what a call really does. Ball speed, paddle english and other tuning
> are playtest territory (CLAUDE.md) and were left alone, except where the code
> contradicted its own documented rule.
>
> **Result**: no CRITICAL or HIGH findings. **3 MEDIUM + 12 LOW, all fixed in
> 0.9.2.** One fix (L-3) changes how the game plays and needs the console
> playtest. The attack surface is small: no network, no FFI, no shell-out, and
> the only outside inputs are the terminal and one local save file.

## Method

- Every line of first-party code read, then a second independent read by a
  reviewer briefed only on the code. Both reached the same core defects.
- Each suspect reproduced with a throwaway harness before anything was changed.
- Toolchain sweeps: `cyrius vet`, `deny`, `lint --strict`, `build --strict`,
  the bounds-checked mode, the poison allocator, and aarch64 under qemu.
- Each repair mutated to confirm a test fails without it.

Severity follows the first-party standard: CRITICAL (remote / privilege
escalation), HIGH (moderate effort), MEDIUM (specific conditions), LOW
(defense-in-depth or minor correctness).

## Findings

### MEDIUM

**M-1. An arrow key could be read as Esc and quit the game.** `input_poll` and
`input_nav` looked for a whole `ESC [ x` inside one read and treated anything
shorter as a lone Esc. A sequence split across reads therefore quit the game, or
exited the program from the menu. Eleven queued arrows (33 bytes against a
32-byte read) were enough. So was one arrow in application-cursor mode
(`ESC O C`).
*Fix*: one decoder, `input_feed`, keeps its position between reads, and every
screen uses it. A lone Esc is now recognised one poll later.

**M-2. Held keys corrupted the initials and dismissed the score table.** A
movement key is usually still held when the last ball drops. Its repeats typed
`DDD` into the initials and dismissed the table on the first byte. Arrows typed
letters at the prompt, since `ESC [ C` was read as three separate bytes.
*Fix*: post-game screens ignore input until it has been quiet for 30 frames, and
the prompt reads decoded keys (`initials_apply`).

**M-3. A failed or interrupted save destroyed the high scores.** `hs_save`
truncated the file before writing. Under `ulimit -f 0` a valid 57-byte file
became 0 bytes. The failure was also silent.
*Fix*: `hs_save_to` uses the stdlib's `file_write_atomic`, and the table screen
shows `NOT SAVED` if the write failed.

### What L-3 does to play

Measured with a bot that tracks the ball and re-aims every 8 ticks, 200 games on
each build:

| | 0.9.1 | 0.9.2 |
|---|---|---|
| Games clearing all 5 levels | 200 | 200 |
| Mean ticks to clear | 5,575 | 7,405 |
| Worst ticks to clear | 8,331 | 10,264 |

Clears run about a third longer, because a ball that strikes a side now bounces
back instead of carrying on through the row. Speed stays constant: 3,000,000
ticks showed no speed, bounds or zero-`vy` violations. A bot whose aim repeats
exactly every 31 ticks locked into a repeating rally around a last brick, which
a varied paddle does not do. Whether this feels right is a playtest call. To
revert, take the `side == 1` branch out of `world_step`.

## Checklist

1. **Input validation.** Terminal bytes go through the decoder (fuzzed).
   `hs_decode` checks magic, `plen <= 200`, the decompressed length, then the
   HMAC, and `hs_deserialize` bounds `cnt` and the length. `argv(1)` is only a
   tick count.
2. **Buffer safety.** Every `var buf[N]` reviewed. The largest risks are all in
   range: `plain[256]` (plaintext ≤ 200 B, decompress capped at 256), `ini[3]`
   (`pos < 3` guarded), `digits[20]` (i64 is at most 19 digits), `swp[136]`
   (`SWP_SIZE` = 136). Clean under the bounds-checked and poison modes.
3. **Syscall review.** Termios (L-1) and framebuffer ioctls (L-5) now checked.
   Struct offsets for termios, `fb_var_screeninfo`, `fb_fix_screeninfo` and ALSA
   sw params confirmed by reading; the framebuffer offsets also by a read-only
   ioctl on the dev box (2560×1440, 32 bpp, `line_length` 10240). Remaining
   unchecked returns (`nanosleep`, blit `lseek` / `write`, PPM / WAV dumps) only
   drop a frame or a debug artifact.
4. **Pointer validation.** Heap pointers are internal. Brick and table indices
   are bounded by construction.
5. **Command injection.** No `exec` or shell-out. Pass.
6. **Path traversal.** The only built path is `$HOME/.cyrius-bb/scores.cyb`, at
   the player's own privilege. Pass.
7. **Known CVEs.** No network or TLS surface. Dependencies are the latest tags
   (sankoch 2.8.9, sigil 3.13.15, bayan 1.11.1, vani 1.2.10). The recent sigil
   advisories in Cyrius's changelog cover ChaCha20-Poly1305 and X.509; this game
   calls only HMAC-SHA256. **No external CVE database was searched for this
   pass.**
8. **Findings.** This document.

## Reviewed and left as is

- **SIGTERM / SIGHUP leave the terminal raw.** The stdlib has no way to install
  a handler. `ISIG` is off, so these come only from outside; `reset` recovers.
- **The save HMAC key is embedded.** The file is tamper-evident, not
  tamper-proof, by design (`save.cyr`).
- **Decompression runs before the HMAC check,** since the MAC covers the
  plaintext. Output is capped at 256 B and the path is fuzzed.
- **A full audio ring blocks the frame.** Documented in `sound.cyr`; a mixer is a
  playtest-driven refinement.
- **The brick grid sits 3 px off-centre** (margins 8 and 14), and a hit picks the
  first overlapping brick rather than the most overlapped. Visual / feel.
- **`ACT_LAUNCH` is unused** (the ball serves itself), **`tests/cyrius-bb.bcyr`
  is still a placeholder,** and the suite exits with its failure count, per the
  CLAUDE.md test convention (CI gates on the summary line).

## Verification

- `cyrius test`: **382 / 382**, also under `--bounds`, `CYRIUS_POISON=1` and
  aarch64 (qemu). Headless frames are identical across x86_64 and aarch64.
- `cyrius fuzz`: 8,000 save and 30,000 input cases, clean plain, `--poison` and
  `--bounds`.
- **33 / 33 mutations red** (31 suite, 2 fuzz). `file_write_atomic` is checked
  out of band: under a failing write the old file stays intact at 0.9.2 and goes
  to 0 bytes at 0.9.1.
- **Real terminal path**: 10 pty scenarios replayed the findings, each restoring
  termios. A full game ran in a pty (menu, play, pause, mute, game over, initials,
  save, table, quit) and exited 0 with the terminal restored.
- **Unchanged from 0.9.1**: all 11 demo artifacts and `scores.cyb` are
  byte-identical; saves load in both directions; 6.6.6-era saves load; tampered
  files are rejected. Smoke output matches, and the frame after 600+ ticks
  differs as expected from L-3.

## Not verified

- **The framebuffer blit on a real console.** The harnesses avoid `/dev/fb0` on
  purpose, since writing it would scribble on the live display. L-5 is covered by
  unit tests on the geometry only.
- **Audio on hardware.** This account has no access to `pcmC1D0p` (`-EACCES`).
- **Feel**, including L-3 and L-4. All three stay with the console playtest
  (`state.md` Next, item 1).
